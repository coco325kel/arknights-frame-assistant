# 游戏音频控制

仅控制已识别的明日方舟进程的音频会话，不修改系统总音量或其他程序。

## 使用

「快捷操作」新增以下可改键项目，沿用现有热键生效范围，保存或应用后生效：

| 功能 | 默认按键 | 行为 |
| --- | --- | --- |
| 一键静音 | F8 | 切换手动静音 |
| 提高游戏音量 | Ctrl+↑ | 增加 10 个百分点，并请求解除手动静音 |
| 降低游戏音量 | Ctrl+↓ | 减少 10 个百分点，保留静音状态 |

音量限制在 0%–100%，可按住连续调节。已有的 F3 等自定义绑定不被覆盖。
音量结果使用短暂浮动提示，不为每次按键创建托盘通知或写入提示日志。
相邻、同一进程身份、同方向的待执行音量输入合并；增减方向和静音操作之间不合并。队列达到 16 项后，不能合并的新音量输入不再接受，已接受动作仍按顺序执行，静音操作继续接受。超载时不保证每次音量输入均被执行。
「游戏在后台时自动静音」默认开启并持久保存。手动静音与后台自动静音任一成立即静音；回到前台只解除自动部分。
调高时先成功设置对应会话的音量，再恢复出声；后台自动静音继续生效。
部分会话失败后再调低，只更新目标音量；已经出声的会话不重新静音，未成功的恢复请求等最新目标写入成功后继续。新的手动静音操作取代此前恢复请求。

每次调节优先读取默认多媒体输出上活动会话的实际音量，再依次选择其他活动会话、未过期会话。
目标音量同步到该进程在所有活动输出上的会话，并保留到本次游戏进程或 AFA 运行结束。
已有会话成功设置后不持续覆盖 Windows 音量混合器中的音量调整；新设备或新会话会补用最近目标音量。
无会话时保留目标或累计增量，等会话出现后处理。正常退出不回滚主动调好的音量。

在前台通过 Windows 音量混合器解除已被手动静音的已知会话时，AFA 会解除该进程的手动静音意图。
新出现的会话不视为外部解除操作。后台自动静音开启时仍持续执行自动策略。
关闭自动功能或正常退出时恢复自动接管前的静音值，保留手动静音和原有静音。
暂时断开的会话保留恢复记录；退出未能恢复的记录写入 `mute-restore.ini`，下次 AFA 启动且进程身份相同时继续恢复。

## 原生通知模块构建

本次兼容与验收范围为 Windows 11 x64；构建要求 Visual Studio 2022 C++ x64 Build Tools 和 Windows SDK。
在仓库根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build_audio_notify.ps1
```

添加 `-Test` 可运行 `test/native/audio_notify_stop_test.cpp`：仅启动/停止通知监听，不改变音量；验证持有 COM 引用时重复停止仍返回忙，释放后停止成功。

生成 `src/resources/audio/AudioNotify.dll` 与 `AudioNotify.sha256`，中间文件在 `.scratch/audio-native`。
使用静态 C++ 运行库 `/MT`，无需另装 VC++ 运行库。生成文件不提交 Git。
**用 Ahk2Exe 打包 `src/main.ahk` 前必须先执行此构建**，两份资源通过 `FileInstall` 嵌入。
运行时按 SHA-256 校验并以含摘要的文件名提取 DLL，避免不同版本占用同名模块。

通知模块在独立 MTA 线程注册设备与新会话回调，只向 AHK 发送整数消息。
先注册会话通知，再获取会话枚举器并调用 `GetCount`；停止时先注销、结束线程，再卸载 DLL。
通知到达后同步全部活动输出，随后两秒内每 100ms 复查，稳定后每秒巡检。
每批最多四个音频按键共用一次快照，按输入顺序执行并逐次限制边界；成功操作不额外启动设备复查窗口。失败与无会话仍保留重试。无静音、目标音量或待恢复记录时跳过音频枚举；前后台事件和按键仍可立即唤醒处理。
缺少模块、32 位解释器或通知失败时退回 250ms 扫描，并限频记录降级状态。
不保证驱动切换的首帧绝对无声。

## 验证范围

本移植分支完成 Python 分层、事件、翻译检查，现有 `test/scripts/smoke_test.ahk` 加载检查，以及 x64 C++ `/W4 /WX` 编译。
原生停止重试回归测试已通过。
现有冒烟测试使用内存会话验证批处理：四次操作的快照数由 5 次降至 1 次，同时覆盖 10 个百分点、相反方向边界、音量失败后的恢复与后台优先。此结果不代表真实设备延迟或 CPU 改善已经实测。
上述检查不代表 GUI、真实游戏或设备切换验收通过；本分支的人工验收见 [测试清单](../test/test_game_audio_controls.md)。
此前独立打包版本在 Windows 11 的游戏和多输出设备验证仅作为移植背景，不能替代此分支的验证。
本次仅支持和验收 Windows 11 x64。
